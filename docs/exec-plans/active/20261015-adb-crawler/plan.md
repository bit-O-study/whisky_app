## 1. 대상과 데이터 계약 확정
- 앱 1개·기기 1대·매장/지역 1곳을 첫 파일럿으로 고른다. 특정 앱을 임의로 확정하지 않는다.
- 실제 앱 패키지/버전, 로그인·성인 확인·매장 선택 흐름과 검색/주류 카테고리 진입점을 조사한다.
- ADB 기기 목록과 연결 승인을 확인하고 지정 serial로만 명령을 실행한다. 기기 하나에 작업 하나만 실행한다.
- 앱 표시 가격과 웹 가격이 다른 경우 source만 같다고 덮어쓰지 않도록 앱 채널·지점·회원 조건 계약을 먼저 정한다.

## 2. 추출 가능성 검증: 10~20개
- ADB로 앱 실행/화면 캡처를 수행하고 UI hierarchy에서 resource-id, text, content-desc와 bounds를 먼저 읽는다.
- 화면 텍스트가 노출되지 않는 부분만 캡처+OCR 후보로 둔다. WebView/캡처 제한/한글 입력은 앱·기기에서 검증하며 가능하다고 가정하지 않는다.
- 고정 좌표 대신 UI 요소로 이동하고 각 이동 후 예상 화면/상품 식별자가 맞는지 확인한다. 구조를 못 읽는 화면은 제한된 앵커 기반 fallback으로 처리한다.
- 검색 결과 → 상품 상세 → 가격/용량/조건 수집 → 복귀의 상태 전이를 기록한다.
- 첫 파일럿은 원본 XML/캡처와 JSON만 저장하고 DB에 쓰지 않는다.

## 3. 정규화와 매칭
- 원본 필드: 앱/버전, source, 상품 ID/상품명, 용량, 도수, 구성/수량, 일반가/행사가/회원가/쿠폰가, 지점/지역, 재고 표시, 관측 시각, 읽은 원문, 추출 방식, 근거 경로.
- 판매처 상품 ID를 우선 사용한다. 없는 ID/URL/가격은 만들어내지 않는다.
- 품목 매칭은 브랜드·제품/숙성·용량·도수·세트 구성을 비교한다. 동일 이름의 700ml/1L 및 세트는 분리한다.
- 0원·품절·숫자 누락·OCR 불확실·매장/회원 조건 불명은 검토 대상으로 보낸다. 재고 없음과 수집 실패를 구분한다.
- 현재 ingest-preview 입력에는 매장·채널·회원 조건이 없으므로 검토 JSON에 보존한다. 의미를 손실하는 기존 필드 변환은 하지 않는다. 실제 적재 전 가격 계약과 필요한 마이그레이션을 별도 설계한다.
- 스크린샷은 상품 영역 중심으로 저장하고 계정·주소 등 개인정보 노출을 최소화한다. 원본 산출물은 Git에 넣지 않는다.

## 4. 배치/복구
- 제안 위치: backend/crawler-adb (기존 웹 크롤러는 유지). transport(adb), navigation(state machine), sources(app adapter), extraction, normalization, checkpoints, report로 분리한다.
- 한 기기의 화면 조작은 직렬 처리. 완료된 원본의 파싱/검증은 PC에서 처리한다.
- 카테고리 순회로 상품을 발견하고 기존 목록 검색으로 보완한다. 검색 몇 개만으로 전체 수집이라고 보고하지 않는다.
- 화면/상품 ID 중복 검출, 최대 스크롤/상품 수, 타임아웃, 제한 재시도, 오류 백오프를 둔다.
- 같은 화면 반복·로그인 풀림·팝업·기기 연결 해제 시 상태와 마지막 성공 상품을 저장하고 중단한다. 다음 실행은 체크포인트에서 재개한다.
- 구매/장바구니/쿠폰 사용/계정 설정 변경은 수집 흐름에 포함하지 않는다. 인증/인증문자가 요구되면 사용자 조작을 기다린다.

## 5. 적재 연결 및 운영
- 기존 ingest-preview → safety-gates → ingest-write를 재사용하되 ADB별 근거/조건 검증을 추가한다. 기존 점수에 맞춰 임의 점수를 주어 통과시키지 않는다.
- EMART/LOTTEON 신규 품목 자동 적재 제한 등 기존 규칙은 유지한다.
- 최초 50개 정도의 관측 표본에서 상품·용량·금액·조건을 대조한다. 중요 항목 불일치는 자동 적재에서 제외하고 원인을 고친다.
- 같은 배치를 다시 실행해 중복 기록이 생기지 않는지 확인한다. 실패한 수집으로 정상 가격을 삭제하거나 0원으로 바꾸지 않는다.
- 수집 성공률/검토율/상품당 처리 시간/가격 오인식/재시도/누락 범위를 보고한다. 주기는 실측 처리량과 앱 특성을 보고 정한다.
- PC 작업 스케줄러에서 실행하며 USB/디버깅/기기 사용 가능 여부를 먼저 확인한다. 서버리스 웹 배포에서 물리 기기를 직접 제어하지 않는다.

## 완료 기준
- 파일럿: 선택한 앱의 샘플 화면에서 상품·가격·용량·조건 추출과 원본 근거 확인.
- 안정성: 페이지 중복, 연결 끊김, 재실행, 인증 만료, 품절, 회원가, 잘못된 OCR 사례 검증.
- 통합: 기존 상품과 정확히 연결되고, 매장/조건별 가격이 섞이지 않으며, 웹에 관측 시각과 조건이 표시됨.
- 대상 앱과 DB 설정이 확정되기 전까지 특정 앱 수집 성공이나 실적재 가능을 보장하지 않는다.

## 구현 단계 변경 (2026-10-15)
첫 반복 수집기는 scripts/adb/collect.mjs에 둔다. 목록에서 판매처 배지/상품명/가격/할인조건을 한 번에 읽어 상세 진입 비용을 줄인다. 현재 위스키 카테고리, 이마트/트레이더스 전환, 중복 제거, 체크포인트, 제한 재시도/스크롤, 정체 종료를 구현한다. 재개는 기존 결과를 유지하고 홈에서 다시 순회하는 방식이다. 원본 전체 XML/화면은 계정정보가 섞일 수 있어 저장하지 않고 상품 텍스트만 보존한다. 결과는 검토 전용이며 데이터베이스 계약을 변경하지 않는다.
