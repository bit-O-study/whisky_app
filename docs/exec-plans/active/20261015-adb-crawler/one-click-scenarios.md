# 4개 마트 양주 수집: 시나리오와 원클릭 실행 설계

작성일: 2026-10-15. 대상: 이마트, 코스트코, 이마트 트레이더스, 롯데마트. 이번 산출물은 실행 설계이며, 아래 명령/버튼/worker는 아직 구현하지 않았다. 기기 조작이나 DB 변경을 수행하지 않았다.

## 목표와 범위

최초에 기기·앱·로그인·판매처별 기준 매장을 설정한 뒤 `전체 수집 시작` 한 번으로 준비 검사 → 판매처별 수집 → 상품 매칭 → 검토 분류 → 결과 보고를 수행한다. 인증 만료나 화면 변경처럼 자동 처리할 수 없는 상황은 대기 상태와 안내를 보여준다.

1차 범위는 위스키·브랜디/코냑·진·럼·보드카·테킬라·리큐르다. 앱의 양주 분류를 조사한 뒤 정규화한다. 와인·맥주·전통주·사케는 기본 제외하되 상품 발견 결과를 무조건 삭제하지 않고 제외 사유를 남긴다. 세트/선물 패키지는 단품과 별도 취급한다.

수집 모드:
- 발견: 주류/양주 카테고리를 순회해 신규 상품 후보를 찾는다. 카테고리 전체 열람이 불가능하면 브랜드/상품명 검색으로 보완하고 검색 기반의 제한된 범위라고 보고한다.
- 갱신: 이미 검증한 판매처 상품 ID/상세 동선의 가격과 재고를 다시 확인한다.
- 재개: 지정 run의 미완료 상품부터 이어간다. 진행 위치뿐 아니라 앱/매장/검색 조건도 복원·검증한다.

## 공식 자료로 확인한 범위

- 이마트 공식 앱 웹에는 검색 진입 및 행사 정보가 있다. 실제 기기의 상품별 양주 가격/용량/재고 노출은 별도 확인한다. [이마트 앱](https://emartapp.emart.com/main/main.do)
- 트레이더스 공식 가입 안내는 이마트 앱에서 트레이더스 홈으로 이동하는 흐름을 안내한다. 이를 시작 동선으로 사용하되 실제 UI 요소는 조사한다. [공식 안내](https://eapp.emart.com/event/detail/tradersclub.do?trcknCode=menu_header)
- 롯데마트GO 공식 앱 소개는 매장 재고 확인을 안내한다. Android 패키지 후보는 `com.lottemart.lmscp`이며 설치된 버전에서 다시 확인한다. 이 안내만으로 양주 가격 전체 수집이 가능하다고 판단하지 않는다. [공식 앱 등록 정보](https://play.google.com/store/apps/details?hl=ko&id=com.lottemart.lmscp)
- 코스트코 공식 온라인 페이지는 매장 상품/가격과 차이가 있을 수 있음을 안내한다. 온라인 가격을 매장 가격으로 대체하지 않는다. [공식 안내가 있는 상품 목록](https://www.costco.co.kr/c/SPO-FY26-P11W4-FOOD)

## 시나리오 1: 이마트

1. 앱 실행 → 현재 로그인/성인 확인 상태 검사 → 이마트 모드인지 확인.
2. 설정한 기준 매장을 선택하고 화면에 표시된 매장명이 설정값과 같은지 검증한다.
3. 상품 검색/주류 카테고리 진입점을 조사한다. 카테고리가 있으면 양주 하위 목록을 순회하고 없으면 검증된 브랜드·상품명 검색 목록을 사용한다.
4. 상품을 열고 상품명, 용량, 도수, 구성, 표시 가격, 행사 기간/조건, 재고를 기록한다. 일반가/행사가/회원가를 각각 저장한다.
5. 상세 화면의 상품과 목록의 상품이 일치하는지 검사하고 근거 XML/상품 영역 캡처를 저장한다.
6. 목록으로 복귀해 다음 상품 진행. 완료하면 누락/가격 미노출/검토 대상과 수집 범위를 보고한다.

분기: 재고만 보이면 inventory-only로 저장하고 가격을 추정하지 않는다. 구매/픽업 화면으로 이동해야 하는 경우 먼저 조회 가능한 지점까지만 조사하며 구매를 수행하지 않는다.

## 시나리오 2: 이마트 트레이더스

1. 이마트 앱의 트레이더스 홈 진입 → 트레이더스 로고/제목 확인 → 트레이더스 기준 매장 선택.
2. 직전 이마트 매장이 남아 있지 않은지 확인하고 별도 source `EMART_TRADERS`로 run을 생성한다.
3. 양주 목록 또는 검색을 통해 상품 상세 순회. 대용량, 2병 묶음, 잔 포함 세트를 분리한다.
4. 일반가와 TRADERS CLUB 등 회원 조건별 가격이 노출되면 별도 관측으로 기록한다. 화면에 없는 가격은 비회원/회원 가격으로 추측하지 않는다.
5. 앱 엔진/로그인 세션은 이마트와 공유할 수 있지만 매장 설정·상품 ID 매핑·체크포인트는 분리한다.

분기: 이마트 모드로 튕기거나 매장이 바뀌면 해당 상품의 가격을 저장하지 않고 올바른 상태로 복구한다. 복구 실패 시 해당 판매처를 중단한다.

## 시나리오 3: 롯데마트

1. 롯데마트GO 실행 → 롯데마트/롯데슈퍼 중 롯데마트 대상인지 확인 → 기준 매장 선택.
2. 공식 안내의 재고 조회 흐름에서 상품 검색을 조사한다. 양주 카테고리/보틀벙커 진입점은 실제 화면에 있는 경우만 채택한다.
3. 상품 상세에 가격이 있다면 상품명·용량·선택 매장·일반/회원/행사 조건과 함께 저장한다. 재고만 있다면 재고만 저장한다.
4. 주류 행사 전단이 별도 제공되면 이미지 OCR 후보를 생성한다. 묶음 적용/카드 할인/행사 날짜를 함께 읽고 검토 대상으로 둔다.
5. source는 신규 `LOTTE_MART`로 제안한다. 기존 `LOTTEON` 상품·가격은 자동 이동/병합하지 않는다. 보틀벙커/다른 점포 형식은 지점/브랜드 문맥을 보존한다.

분기: 롯데온으로 연결되면 채널 전환으로 기록하고 롯데마트 매장 가격으로 저장하지 않는다. 가격 미노출 품목은 price_unavailable 사유를 남긴다.

## 시나리오 4: 코스트코

1. 앱/공식 웹에서 매장별 양주 가격이나 행사 자료가 제공되는지 먼저 조사한다. 로그인은 사용자가 수행한다.
2. 가격과 용량이 표시되는 개별 상품 화면이 있으면 상품번호를 우선 키로 수집한다. 온라인/매장 출처와 지점 적용 범위를 기록한다.
3. 행사 자료만 있으면 이미지/PDF를 원본으로 보관하고 상품명·용량·할인가·할인액·기간·적용 점포를 추출한다. OCR 결과는 우선 검토로 분류한다.
4. 온라인에 양주 가격이 없거나 캡처가 제한된 화면은 unsupported로 종료한다. 해당 상태는 수집 실패나 품절과 구별한다.
5. 온라인으로 관측되지 않는 매장 가격은 선택 기능인 현장 가격표 사진 업로드 → OCR → 검토 경로로 보완할 수 있다. 이것은 ADB 자동 수집 성과로 집계하지 않는다.

코스트코의 매장 양주 전체 목록을 앱만으로 수집할 수 있다는 전제는 두지 않는다. 처음 조사에서 가능 범위를 확정한 뒤 구현량을 정한다.

## 최초 설정 화면

기기 연결(ADB serial 고정), 대상 앱 검사, 판매처별 기준 매장, 수집 대상 종류, 일반가/회원가 포함 여부, 실행 모드를 저장한다. 예시 값이나 기기의 자동 선택 매장을 운영 설정으로 조용히 확정하지 않는다.

로그인 비밀번호/OTP는 어드민 설정에 저장하지 않고 사용자가 기기에서 입력한다. 최초 조사 시 resource-id/text/content-desc 기반 화면 규칙과 앱 버전을 기록한다. 텍스트 노출이 없을 때만 OCR을 붙인다. 고정 좌표만으로 전 화면을 탐색하지 않는다.

## 버튼을 누른 뒤의 실행 순서

1. 어드민에서 `전체 수집 시작` 클릭. 같은 클릭을 중복 전송해도 idempotency key로 run 하나만 만든다.
2. 서버는 설정 버전·대상·작업 ID를 포함하는 작업을 큐에 등록하고 바로 응답한다. HTTP 요청 안에서 크롤링이 끝날 때까지 대기하지 않는다.
3. USB 기기가 연결된 Windows PC의 worker가 인증된 연결로 작업을 가져온다. Vercel 서버가 ADB/USB를 직접 조작하지 않는다.
4. worker는 기기 잠금/연결/인증/앱 설치/매장 설정/다른 실행 여부를 검사한다. 한 serial의 기기 제어 lock은 하나만 허용한다.
5. 기본 순서 이마트 → 트레이더스 → 롯데마트 → 코스트코로 실행한다. 각각 설정된 기준 매장만 순회한다.
6. 각 상품 완료 때 원본 JSON과 체크포인트를 원자적으로 저장하고 진행률·heartbeat를 보고한다. 기기 조작은 직렬, 저장된 원본의 파싱은 별도로 처리할 수 있다.
7. 로그인 필요 같은 판매처별 문제는 해당 job을 needs_action으로 두고 다음 판매처를 실행할 수 있다. 기기 연결 해제처럼 공통 문제는 전체를 needs_device로 대기시킨다.
8. 종료 시 판매처별 성공/검토/미지원/실패/관측 범위를 보여준다. 일부 성공은 partial이며 전체 성공으로 표시하지 않는다.

상태: queued → preflight → running → reviewing → completed/partial/failed/cancelled. needs_action/needs_device는 대기 상태로 두고 사용자 조치 후 재검사한다. 앱/필터/매장 문맥이 바뀌었으면 오래된 화면 좌표로 재개하지 않는다.

## 실행 명령 계약 (아직 구현되지 않은 인터페이스 예시)

Windows PowerShell이 현재 작업 환경의 기본 진입점이다. macOS/Linux용 .sh는 같은 CLI를 호출하도록 나중에 추가한다. .cmd 더블클릭 런처도 동일 CLI를 호출한다.

```powershell
# 최초 설정/연결 점검
.\scripts\crawl-liquor.ps1 doctor
.\scripts\crawl-liquor.ps1 configure

# 네 판매처 수집, 최초 기본값은 검토까지만
.\scripts\crawl-liquor.ps1 run -Sources all -Mode discover -ReviewOnly

# 기존 상품 가격만 갱신 / 한 판매처만 수집 / 끊긴 작업 재개
.\scripts\crawl-liquor.ps1 run -Sources EMART -Mode refresh -ReviewOnly
.\scripts\crawl-liquor.ps1 resume -RunId <작업ID>
.\scripts\crawl-liquor.ps1 status -RunId <작업ID>
.\scripts\crawl-liquor.ps1 cancel -RunId <작업ID>

# 어드민 버튼으로 등록한 작업을 받는 PC worker
.\scripts\crawl-liquor.ps1 worker
```

스크립트와 버튼은 같은 runner/설정/작업 저장소를 사용한다. exit code는 0=정상 완료, 2=일부 완료/검토 필요, 3=기기·로그인 조치 필요, 1=실행 오류로 제안한다. 첫 버전은 수집 시작과 가격 공개 반영을 분리한다. 검증된 adapter와 명확한 일반 가격만 운영 정책을 통과하면 자동 반영하도록 확장한다.

## 제안 구현 경계

```text
backend/crawler-adb/
  src/cli/            # doctor, configure, run, resume, status, cancel, worker
  src/runner/         # 큐 처리, 상태 전이, device lock, heartbeat
  src/device/         # adb 연결, 앱 실행, UI hierarchy, 캡처
  src/sources/        # emart, traders, lotte-mart, costco
  src/extraction/     # UI 텍스트 추출, 선택적 OCR, 조건 파싱
  src/matching/       # 상품/용량/구성 매칭
  src/storage/        # 원본, 체크포인트, 결과/근거 저장
scripts/crawl-liquor.ps1
```

어드민에는 대상/매장 요약과 시작·중단·재개 버튼, 실행 목록, 근거 검토, 매칭 후보를 둔다. 연결된 worker가 없으면 버튼에서 기기 미연결 안내를 보여준다. 고정 task 타입과 검증한 파라미터만 worker에 전달하고 임의 쉘 명령 입력 기능은 만들지 않는다. worker 통신은 외부로 나가는 인증 연결을 사용하며 USB PC 포트를 인터넷에 공개하지 않는다.

## 데이터/마이그레이션 선행 작업

- 현재 코드의 source 집합과 참고 SQL에는 LOTTE_MART가 없다. 실제 DB constraint/enum, 가격 이력, 최신 가격 뷰, 프론트 한글 매핑/추천 source, 어드민 검증을 조사한 뒤 함께 추가한다. LOTTEON은 유지한다.
- 현재 `(liquor_id, source)` 단위 가격에는 매장/회원 조건을 담을 수 없다. raw observation → 조건별 offer → 공개 비교 read model 계약을 먼저 확정한다.
- 원본에는 source, channel, store, source_product_id, 상품명, volume_ml, alcohol_percent, pack_count, price_type, amount, currency, 조건 원문, 행사 기간, stock_status, observed_at, evidence를 보존한다.
- 재시도는 run+판매처상품+옵션+지점+조건 키로 중복 방지한다. 새 run은 새 관측으로 남긴다. 가격 0/수집 실패로 기존 정상 가격을 덮어쓰지 않는다.
- 원본 계정/주소 영역은 제외하고 산출물은 Git에 넣지 않는다. 검토 화면의 근거 자료는 인증된 접근으로 제공한다.
- 외부 URL이 없으면 앱 전용으로 표시한다. 기존 구매 링크를 임의로 만들지 않는다.

| 인증 만료/성인 확인 | needs_action, 인증 후 해당 작업 재개 |
| 매장 자동 변경 / 이마트↔트레이더스 모드 혼동 | 가격 저장 전 검출, 올바른 매장 재확인 |
| 회원가/카드 할인/묶음/700ml와 1L | 별도 조건/상품으로 보존, 일반 최저가와 혼합 없음 |
| 재고만 표시 / 품절 / 검색 결과 없음 | inventory-only/out_of_stock/not_found 구분 |
| XML에 가격 없음 / OCR 숫자 불확실 | 근거와 함께 검토 대기, 임의 가격 공개 금지 |
| 목록 무한 반복 / 팝업 / 앱 버전 변경 | 제한 재시도, 체크포인트와 명확한 실패 사유 |
| USB 해제/PC 재시작/취소 후 재개 | 마지막 완료 상품 이후부터 재개, lease 만료 후 중복 제어 방지 |
| 코스트코 가격 미노출 | unsupported로 종료, 전체 수집 성공이라고 표시하지 않음 |

## 개발 순서와 완료 기준

1. 네 앱 현장 조사표: 패키지/버전/화면 경로/양주 가격 노출/XML 가능 여부. 이 단계에서 코스트코의 자동화 가능 범위를 먼저 판정한다.
2. 공통 runner + 이마트 1매장 20개 파일럿. 20개 전수 대조, 중요한 가격/용량/조건 오인식은 검토 또는 수정.
3. 트레이더스·롯데마트 adapter. 각 20개 표본과 판매처/매장 전환 검증. 롯데마트 가격 미노출이면 재고/행사 자료로 범위를 명시.
4. 코스트코는 조사 결과에 따라 상품 상세 또는 행사 자료 수집기로 구현. 접근 가능한 자료가 없으면 미지원 결과를 정식으로 처리.
5. 50개 배치의 중단·재개·중복·인증 만료 테스트. 같은 run 재실행 중복 가격 0건, 실패로 정상 가격 훼손 0건.
6. PowerShell 진입점 완성 → 어드민 버튼/진행 화면 연결 → 검토/가격 반영 연결.
7. 첫 3회 실행 결과의 상품당 처리 시간과 실패율로 주기 결정. 초기에는 수동 실행, 안정화 후 하루 1회부터 검토한다.

아직 확인해야 할 실제 기기와 판매처별 기준 매장은 최초 설정 항목으로 남긴다. 이 문서 작성 단계에서 해당 정보가 없어도 구현 경계와 실행 계약은 확정할 수 있지만, 실제 화면 선택자와 수집 성공은 기기 조사 없이 확정할 수 없다.
